# Days 29–30 — Final Capstone: Design & Build a Real System

**Track:** SQL · **Stage:** 6 — Capstone · **Difficulty:** Advanced

**Prerequisites:** Days 01–28. This is where 28 days become one build.

## Goal

Independently design and build a complete relational system — schema, constraints, CRUD, analytics, transactions, indexes, and a performance report — with real design decisions and no step-by-step solution.

## The Full Assignment

Everything you need is in **[../projects/07-capstone.md](../projects/07-capstone.md)**. The short version:

> **Build "LocalEvents"** — a ticket-booking platform: organizers, events, venue seats, customers, bookings, payments. Deliver:
>
> 1. **Schema** (3NF + two justified denormalizations, constraints, keys) — with a written design memo
> 2. **Seed data** — 5 events, 40+ seats, 10 customers, realistic bookings
> 3. **A transactional booking flow** — book two seats atomically; prove failure leaves nothing behind
> 4. **Analytics** — revenue per event, occupancy %, top customers (windows + GROUP BY)
> 5. **Performance work** — scale to 100k+ rows (`generate_series`), index the hot queries, EXPLAIN ANALYZE before/after with numbers
> 6. **Self-review + interview drill** — defend every decision out loud

## Suggested Split

**Day 29 — Design & Build**

- Morning: read the full spec; draw the ER diagram (Mermaid, in `shared/diagrams/` style)
- Afternoon: write the DDL + constraints; write the design memo (Day 26 format)
- Evening: seed data; build the booking transaction; test the failure scenario

**Day 30 — Analytics, Performance & Defense**

- Morning: the five analytics queries (from memory where possible)
- Afternoon: scale up, profile, index, re-profile — write the before/after report
- Evening: the mock-interview defense (the spec's questions, out loud, recorded)

## Rules

1. **No solutions for the design exist** — that's deliberate. Any defensible choice is correct; unexplained choices are not.
2. Use your **Day 27 style guide** — every rule you wrote, applied.
3. When stuck for >20 minutes on a *concept*, go re-read that day's lesson. When stuck on a *decision*, write both options' trade-offs and pick one — that's the job.
4. Commit your work (schema files, queries, memo, report) into this repo under `sql/projects/capstone-work/` — create that folder yourself; it's intentionally empty until you fill it.
