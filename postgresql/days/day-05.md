# Day 05 — Primary Keys, Identity & Sequences

**Track:** PostgreSQL · **Stage:** 2 — Modeling in PG · **Difficulty:** 🟢→🟡

## 🎯 Goal

Stop typing ids by hand: identity columns and sequences, and what they guarantee.

## 🧠 Fundamentals

**The problem:** every table needs a PK; humans shouldn't mint them. PostgreSQL offers:

**1. Identity columns (modern standard, prefer this):**

```sql
CREATE TABLE customers (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL
);
INSERT INTO customers (name) VALUES ('Ayesha');   -- id auto-assigned
-- INSERT INTO customers (id, name) VALUES (1, 'X');  -- ERROR with ALWAYS
```

`GENERATED ALWAYS` — the column is the system's, period. `GENERATED BY DEFAULT` — the system fills it unless you force a value (escape hatch; dangerous for collisions — prefer ALWAYS and grant yourself BY DEFAULT only for data loads).

**2. `SERIAL`/`BIGSERIAL`** — the legacy mechanism (a hidden sequence + default). You'll see it everywhere in old code; know it, don't start with it.

**3. Sequences directly** — when you need a *numbering rule*, not a row identity:

```sql
CREATE SEQUENCE invoice_numbers START 1000;
INSERT INTO invoices (id, invoice_no) VALUES (1, NEXTVAL('invoice_numbers'));
SELECT CURRVAL('invoice_numbers');      -- what this session just took
SELECT LASTVAL('invoice_no_seq');        -- last value this session got from any seq
```

**Facts that matter:**

- Sequences are **gap-tolerant** — a failed insert still consumes a number. Gaps are normal; do NOT build business logic on "no gaps."
- Identity ≠ concurrency-safe ordering: ids arrive roughly in order, but a *lower* id can commit after a higher one. Use a timestamp column for ordering.
- Getting the id you just made: `INSERT ... RETURNING id;`

## 🔍 Why It Matters

Surrogate keys via identity are the default of virtually every table you'll ever write. And "why are there gaps in my ids?" is a top-5 production non-mystery once you know sequences.

## 💡 Mental Model

> An identity column is a **queue ticket machine**: it never repeats, never reissues, and skipping numbers is fine (someone took a ticket and left). A manual sequence is a **numbered receipt pad** for cases where the number itself has business meaning.

## 💻 Examples

```sql
CREATE TABLE orders_pg (
    id        BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id   INT NOT NULL,
    status    TEXT NOT NULL DEFAULT 'pending',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

INSERT INTO orders_pg (user_id) VALUES (1) RETURNING id, created_at;
INSERT INTO orders_pg (user_id) VALUES (2), (3) RETURNING id;
SELECT MAX(id), MIN(id) FROM orders_pg;
```
